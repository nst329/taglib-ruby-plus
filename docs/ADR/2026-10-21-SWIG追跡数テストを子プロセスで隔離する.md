# SWIG追跡数テストを子プロセスで隔離する

## 背景

Linux Ruby 4.0.7のCIで、close後の追跡数が期待値50から49へ減り、解放テストが失敗した。これは追跡数が増える解放漏れとは異なる。従来のテストは他のテストが残したFileも含むプロセス全体の数を比較し、その間に発生するGCとfinalizerの影響を排除していなかった。

## 決定と理由

専用子プロセスでGCを実行した後、自動GCを停止して測定する。Fileを開き、Tag・ItemMap・Item・CoverArtを借用してcloseする操作を100回繰り返し、各回で追跡数が基準値へ戻ることを確認する。他のテストのfinalizerによる減少を除外しつつ、明示closeによる解除漏れは引き続き検出するためである。

GC compaction中の安全性は既存の別子プロセステストで引き続き検証する。今回native実装や公開APIは変更しない。

## I/Oと検証

合成操作に既存の小さなMP4 fixtureを読み取り専用で使用する。測定を100回へ増やすためfixtureの読込回数は増えるが、書込み・全面コピーは追加しない。実作品にはアクセスしない。

macOS arm64 Ruby 4.0.7で対象テスト30件が成功。Linuxの結果はCIで別途確認する。
