# ADR: chapter計画の責務を整理しtitlの再読込を減らす

日付: 2026-10-21
状態: 採用

## 判断と理由

- 欠落参照計画の成功・拒否で重複していた原本世代の束縛と発行記録を、一つの非公開関数にまとめる。登録権限の判断を分散させず、公開status・reason・拒否順序は維持する。
- 限定修復の解析中に組み立てていたQuickTime検証条件を非公開関数へ分ける。解析・計画値の変換・編集登録の責務を読み分けやすくするためであり、追加解析は行わない。
- 構造入口の拒否計画を作る補助関数をprivateとする。外部から呼ぶ機能ではなく、同一セッションの公開計画APIからだけ使うため。
- titl検証を配置・headerとpayload・文字列表現へ分ける。UTF-8/UTF-16の受理条件とエラー文は変更しない。使用していない変数と、参照されない保存済み計画変数を除く。

## I/Oへの影響

従来の編集計画はtitl atom全体を個別取得した後、署名・描画のためにmoov全体を取得し、titl本文を重複読取していた。上限と構造を検証した後にmoovを取得し、その部分bytesでtitlを検証する。titl専用の追加読取をなくし、moovの全体取得は一回に保つ。診断のcapture_raw=false経路は従来どおりtitl範囲だけを読み、moov全体やmdat本文を取得しない。

moovのメモリ上限と保存時の独立検証は維持する。未対応titlも編集計画ではmoov取得後に拒否するため、拒否時の読取bytesが増える場合はある。対応する入力の重複読取削減を優先し、未対応時にも64 MiB上限を超えない。保存コピー回数とmdat走査は増やさない。速度やI/O削減率は未計測。

## 検証

合成fixtureでtitl付き欠落参照の限定計画を作り、moov全体の読取が一回、その後のmoov内個別読取が0件であることを観測する。既存の参照・専用track除去・限定修復・保存失敗検証も実行する。実作品は操作しない。

結果: 変更Ruby 4ファイルの構文チェック成功。関連4テストファイルは72 tests / 869 assertions、失敗・エラー・省略0。titl付き計画でmoovの一回取得と以後の個別読取0件を確認した。git diff --checkも成功。全体テストは実行していない。
