# MP4公開APIのI/O削減

状態: 採用・実装済み

## 背景と現状

対象はv2.3.2.23の `require "taglib_plus"` と `TagLib::Plus::MP4.open`。
openと各公開操作のSHA-256、参照解析の前後SHAとmdat保持署名、nativeの原子的保存の入れ子、generic復元前のコピー、mdir生成用の媒体コピー、併存contextの読取用コピーが媒体サイズに比例するI/Oを発生させている。

## 決定と理由

- `open(path, verification: :stat)`を通常モード、`:sha256`を厳密モードとする。通常モードでは開いた読取handleとpathのdev/ino/size/mtime/ctime（秒以下を含む）を前後照合する。変更を検出したセッションは再利用せず再openを求める。
- 通常モードはOSのstat属性が同一に見える変更まで検出しない。ctimeにより同サイズ・mtime復元の通常の書換えも検出するが、特殊なファイルシステムや属性偽装に対する内容同一性の証明ではない。厳密モードは前後のSHA照合も行う。どちらも外部writerとの排他や、最終照合とrename間の競合排除、走査中に変更して元へ戻す攻撃への完全な保証はしない。
- metadata・chapter・診断はFile単位の不変値として遅延cacheする。世代変更時は操作を拒否し、原本保存後は検証済みbaselineを採用して診断cacheを破棄する。全媒体bytesは保持しない。
- 参照の構造解析とmedia内容署名を分離する。通常診断・保存前の構造検証ではmediaをhashしない。媒体保持は保存時の独立検証で確認する。
- 候補生成は一回。metadata編集は既存mdir単独も含めatom計画による一回の出力とする。contextがない場合はコピー後のnative writerを使い、内部の原子的保存を重ねない。mdir生成・複数context読取にはmediaもtrackも持たない小さいmetadata専用MP4を使う。
- metadataとchapterは同じ候補へ適用し一度だけ公開する。Neroはmetadata専用領域で生成して最初のmoov出力へまとめる。実測で候補内の全媒体移動が見つかったためである。QuickTime変更時は対象外trackのsample署名で保持を検証し、変更していないchapter形式の値も照合する。
- 通常コピー中に原本全体SHAとmdat署名を共有計算する。出力は保存後に独立して読み直す。コピー中のhashだけで出力保持を証明しない。atom置換コピーにも同じ走査方式を適用する。
- 無変更の原本保存はコピーも全体hashも不要とする。この場合の `source_digest` / `output_digest` は通常モードではnil。計算していないSHAを返さない。実際に出力する保存では正しいSHAを返す。厳密モードの検査用SHAは実測値を返せる。

## 却下案

全操作SHAは大容量媒体の小さいmetadata操作に不釣合いなため通常モードには採用しない。statをSHAと同等の保証として説明しない。全媒体cache・永続cache・外部APIへのInternal露出は不要であり導入しない。

## 検証

[I/O設計](../mp4-public-io-design.md)と[検証記録](../Memos/2026-10-16-MP4公開APIのI-O性能検証.md)に詳細を記録する。通常itemの論理比較で見えないpurlのlocaleも、出力raw署名を独立比較して保持を確認する。

変更前後の公開操作について、読取/書込bytes、全体hash/コピー回数、一時領域最大使用量、経過時間を記録する。小さいfixtureと大きいmdatで傾向を比較し、計測対象・限界を明示する。競合と各保存phaseの失敗、metadata完全置換、wire値とartwork/purl、両chapter形式を回帰検証する。
