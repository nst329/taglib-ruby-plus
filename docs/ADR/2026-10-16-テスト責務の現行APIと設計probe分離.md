# テスト責務を現行APIと設計probeに分ける

状態: 採用

## 背景

Plus APIの製品テストと、実装前に作ったDocument/Update/SavePlanの設計probeが同じテストツリーにあり、どのテストが現行仕様を保証するか分かりにくかった。

## 決定

- `test/plus_mp4_api_test.rb`を現行`TagLib::Plus::MP4`の受入テストとして扱う。
- `test/plus_api_design_probe_test.rb`と`test/support/plus_api_design_probe.rb`は前案の保存境界を記録する履歴として残す。
- `test/README.md`に責務、実行範囲、外部fixtureを必要とするprobeの扱いを記録する。
- `Rakefile`に現行Plus APIだけを実行する`test:plus_mp4`を追加する。
- `Rakefile`の全体テストはtest-unitとminitestを`test:unit`、`test:minitest`へ分け、`test`から順に実行する。

テストファイルを大きく移動しないのは、既存のglob実行・gemspec配布一覧・過去の検証記録への参照を壊さないためである。

## 影響

現行APIの回帰確認を短いコマンドで実行でき、旧設計probeの成功を現行APIの保証と誤認しにくくなる。runnerを分けることで、minitestのautorunがtest-unitの実行を奪う問題も避ける。全体テストでは両runnerを順に実行し、設計probeを履歴として再現できる。
