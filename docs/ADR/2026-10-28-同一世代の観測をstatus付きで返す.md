# ADR: 同一世代の観測をstatus付きで返す

日付: 2026-10-28
状態: 採用（2.3.2.42）

## 背景

`diagnose(area)`は領域ごとに`{status:, data:, issues:}`を返すが、完全な読取値は別API（`metadata`、`chapters`、`chapter_samples`、`info`）を呼ぶ必要があった。MListNewのようにmetadata・chapter・trackをまとめて確認する利用者は、破損の有無を例外で受け取りながら複数APIを呼び分けており、同じ世代の値を集める意図が呼出側へ漏れていた。metadata診断と完全snapshotも別々のnative読込みになっていた。

## 決定

`File#observation(areas = OBSERVATION_AREAS)`を追加する。既定は`metadata chapters chapter_references chapter_timing chapter_samples tracks`で、戻り値は領域名をキーにした深く不変なHashとし、各値は`{status:, data:, issues:, value:}`とする。

- `value`は利用者向けの完全読取値。`status`が`:complete`でない場合は`nil`を基本とし、chapterは形式別に`nero`/`quicktime`のstatusで値を分ける。
- 既存の`diagnose(area)`の`data`と`issues`をそのまま使う領域は、`value`に同じ`data`を返す。chapter参照・chapter時間は通常時は診断行、診断失敗時は構造診断の部分結果になる。
- malformed/unsupported/limitは例外にせず、領域別の`status`と`issues`へ集約する。
- `source_changed`、`io`、`closed`、`pending_changes`は利用者の操作継続に影響するため再送出する。保存待ちのchapter編集がある場合、観測は保存済み世代を返さず拒否する。
- 未知の領域名と重複指定は`ArgumentError`で拒否する。
- metadataは`metadata_diagnostics`と`metadata_snapshot`を同じnative読込みで取得する。完全読取に成功したsnapshotは、その時点で編集候補が未設定なら以後の編集候補にも使う。
- chapterは既存の診断結果を共有し、`:complete`の形式だけ`chapter_reader`の保存済み値を公開値へ変換する。未保存の編集は反映しない。

## 却下案

- 破損も例外で返す案は、複数領域をまとめて観測する用途で最初の破損が後続領域を隠すため採用しない。
- `diagnose`の戻り値へ`value`を常に追加する案は、既存診断の形状とI/Oを変えるため採用しない。
- `observation`専用の新しい診断schemaを全領域に作る案は、既存診断との二重実装になるため採用しない。

## I/Oへの影響

領域間で共通の診断cacheと世代を再利用し、metadataとchapterは同じnative読込みの結果を編集候補へ引き継ぐ。chapter samplesとtracksは従来のAPIと同じ読込みを1回だけ行う。観測は読み取り専用で、保存・pending変更・原本書換えを行わない。fileのopen回数は増やさない。

## 検証

`test/mp4_observation_test.rb`を追加し、実MP4でchapter・metadata・tracksの一括取得、malformed chapterで他形式を保持、malformed metadataで例外にせず`value: nil`、未保存chapter編集時は保存済み値を返すこと、未知・重複領域の拒否、既定領域の一括観測を確認した（4 tests / 27 assertions）。metadataは観測値が編集候補として再利用されることも確認した。既存のTest::Unit 659 tests / 114100 assertionsとMinitest 12 runs / 24 assertionsは失敗・エラー0（実ファイル未指定などの省略を除く）。

## 追記: 2026-10-28 `chapters`のsnapshot読取もRuby readerへ統一

`File#chapters`の編集候補は、native `chapter_snapshot`を追加openして取得していた。ChapterReaderの完全読取値とnative値の照合のためだけにnative handleを開き、同じchapter値を二度読んでいた。

編集候補を同じ世代の`chapter_reader`から直接構築し、`read_chapters`・`diagnose(:chapters)`・`observation(:chapters)`と同じ読取結果を共有する。`require_complete!`を通すため、不完全な原本は従来どおり`code: :malformed`または`:unsupported`の`Error`で拒否する。native値との照合は行わないが、保存時の独立検証は従来どおり残る。

効果はsnapshot取得あたりnative open 1回とchapter値の二重読取の削減。`test/mp4_observation_test.rb`に、`read_native`を禁止した状態でも両形式のsnapshotを取得でき、2回目が同じ値を返す回帰を追加した。
