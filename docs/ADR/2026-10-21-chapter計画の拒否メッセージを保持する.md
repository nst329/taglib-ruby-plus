# ADR: chapter計画の拒否メッセージを最小限保持する

日付: 2026-10-21
状態: 採用

## 背景と判断

エラーログを少しだけ調査しやすくするため、QuickTime除去計画に不変の`message`を追加する。既存のstatus/reason/reason_codeと安全判定は変えず、捨てていた例外messageを保持する。計画を登録できない場合のError本文とissuesにも同じmessageを渡す。Nero読取拒否も元の理由を保持する。

字幕・未知handler sourceの拒否には、最初の該当参照のsource_track_id、handler、target_track_id、target_existsを添える。大量の参照やpayload、ファイル全pathを列挙せず、構造未対応では従来の`unsupported udta/titl`をそのまま使う。限定修復の登録拒否issuesにも、既に得た具体的messageを保持する。

## 理由とI/O

新しいloggerや自動stderr出力は追加せず、呼出し側が既存ログへ具体理由を載せられるようにする。取得済み例外・参照行だけから短い文字列を作り、追加の読取・再解析・保存を行わない。CPU/メモリの追加は短い文字列と参照行の検索に限定し、I/O削減率は主張しない。

## 使用例と範囲

```ruby
plan = file.plan_quicktime_chapter_removal
logger.warn("QuickTime chapter: #{plan.reason_code}: #{plan.message}") if plan.status == :blocked
```

titlの許可、欠落参照用の新計画API、構造検査の統一は別ADRで実装した。ログ改善を理由に拒否を解除する変更は行わない。

## 検証

変更したRuby 4ファイルの構文チェック成功。設計確認・QuickTime除去・chapter参照・限定修復の4テストファイルを実行し、71 tests / 863 assertions、失敗・エラー・省略0。titl payload保持、欠落参照計画、拒否messageの伝達を確認した。実作品には操作していない。
