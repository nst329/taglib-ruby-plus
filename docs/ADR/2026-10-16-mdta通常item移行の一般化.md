# Apple系mdtaへの通常item移行を共通化する

## 状態

採用。2.3.2.21以降の実装へ反映する。

## 背景

字幕mux後の単一`mdta`では、保存元の`mdir` snapshotにある通常itemと、保存先の数値`mdta` keyが異なる。
`purl`だけをraw atomで移す実装では、`artist`や`title`などApple系の通常itemを含むsnapshotで、保存後の表現差を検証できなかった。

## 決定と理由

- `Tag::MDTA_PROPERTY_KEYS`で対応付けられる`title`、`artist`、`description`、`show`と、raw保持が必要な`purl`を移行対象にする。
  対応表を増やせる既存のproperty定義を正本にし、任意の4文字コードを推測しないため。
- 移行対象の通常itemは、既存`mdta` contextの`keys`へ不足キーを追加し、同じ数値indexの`ilst` itemへUTF-8 data atomを保存する。
  `purl`は保存元rawのdata type・locale・payload・順序を使い、他の文字列itemはdata type 1・locale 0に限定する。
- 移行対象以外の通常itemはnative経路で保持し、保存後のatom拡張で移行対象のfourcc itemだけを数値itemへ置換する。
  未対応itemを黙って捨てず、既存writerの拒否・検証契約を残すため。
- native一時保存の検証は、移行後snapshotの値とraw digestを比較する専用経路にする。
  native writer前の通常item表現と、拡張後の数値key表現を同一の厳密比較へ渡さないため。
- 保存先の既存key、対象外metadata、chapter、media payload、原本SHAを保存前後に検証する。
  moov再配置やchunk offset変更の影響をmetadataの値比較だけで見逃さないため。

## 影響と制限

`purl`、`title`、`artist`、`description`、`show`を含む`mdir` snapshotを、既存単一`mdta` contextへ復元できる。
保存先に存在しない対応keyは末尾へ追加し、既存keyはindexを維持する。
対応表にない通常item、複数context、fourcc `purl`、不正atom、raw不一致は従来どおり自動変換せず失敗する。
通常itemのlocaleや非UTF-8型を一般化して推測する機能は追加しない。
