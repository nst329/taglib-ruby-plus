# mdta数値key保存の回帰検証

## 前提

- 修正版: taglib-ruby-plus 2.3.2.19。native ABIとTagLibパッチは変更していない。
- Ruby 4.0.7、パッチ済み実TagLib 2.3.2、FFmpeg/FFprobe、独立Ruby atom parserを使用。
- native参照先はDYLD_LIBRARY_PATH=/private/tmp/purl-taglib-install/libで明示。
- 全て合成MP4と一時ディレクトリで実行し、ユーザーファイルは変更していない。
- DocsとdocsはこのmacOS環境で同じディレクトリ。Gitの既存表記はdocsを維持する。

## 修正前の再現

修正前に公開setterの回帰テストを追加した。use_metadata_tagsで生成した単一mdta MP4に
purlを新規追加してsaveし、close・独立open後に更新すると、原報告と同じ
restored purl raw verification failedが発生した。
3 tests / 10 assertions、1 failure / 2 errors。raw保持テストでも同じ例外を再現した。
原因は通常itemのnil同士の比較で不変と判定し、数値key rawをfourcc用復元へ渡したこと。
nativeでは全mdtaキー共通のchangedKeys/removedKeys/rawItems管理が正常に動作する。

## 修正・整理

- 自動raw保持は元の通常item署名が存在し現在と一致する場合に限る。
- 明示snapshotのrawも含め、数値keyをfourcc復元へ渡さない。
- 全mdtaキーを既存native処理で保存する。purl専用のmdta setter処理や変更判定は追加しない。
- 保存制御とraw保持対象選択を分離し、atom作業コピーの作成・mode保持・置換・cleanupを共通化。
- 保存後検証、例外、警告、原本の原子的置換条件を維持する。

## 実TagLib・合成MP4・独立再読込

| ケース | 確認した結果 |
| --- | --- |
| 新規mdta purl追加 | 新URLを保存し、close後の独立openで一致 |
| 既存mdta purl変更 | 更新URLと一致、単一mdtaのまま、fourccを生成しない |
| 同値設定 | metadata raw item bytesが完全一致 |
| 削除 | 独立openで値なし、他metadataとmediaを保持 |
| 他タグのみ更新 | 未編集purlのdata type 33/1、locale 1041/7、bytes、値順、raw digestを保持 |
| purlと他タグの同時更新 | 両方の新値を保存、対象外のraw metadataを保持 |
| 通常mdir purl | 同値・他タグ更新時のraw保持、変更・削除を確認 |
| 対応済み複合context | 既存snapshot復元・再適用・削除・失敗テストが成功 |
| File snapshot復元 | 数値key追加・既存更新、複数locale、他mdta keyの同時復元が成功 |
| Tag snapshot復元 | 数値key rawをfourccへ渡さず保存し、独立openで値・raw digest一致 |
| 保存後検証失敗 | 原本bytes不変、未commit、一時ファイルを削除 |
| atom変換途中の失敗 | 部分出力と外側の一時コピーを削除、原本bytes不変 |
| media | FFprobe全packetのstream/size/SHA-256が一致 |

## 最終検証

- 変更Rubyファイル、version、gemspecの構文チェック成功。git diff --check成功。
- gemspec_check成功。source gem 2.3.2.19のローカル生成成功。
- 関連4 suite: 69 tests / 754 assertions、失敗0・エラー0・省略0。
- 全Test::Unit suite: 448 tests / 3119 assertions、失敗0・エラー0、既存省略13件。
- Minitest suite: 12 runs / 24 assertions、失敗0・エラー0、5 skips。
  isolated native probeの追加ビルドを要する既存条件によるskip。
- rake testはmacOSの子プロセスでDYLD環境が落ち、消失済み旧libtag参照先でloadに失敗した。
  同じtestファイル群をbundle exec rubyの同一プロセスでロードして検証した。
  MinitestとTest::Unitのautorun混在では後者が走らないため、別々に実行した。

実行例:

```sh
DYLD_LIBRARY_PATH=/private/tmp/purl-taglib-install/lib BUNDLE_PATH=/private/tmp/purl-gems \
  /opt/homebrew/opt/ruby/bin/bundle exec ruby -Itest -Ilib -e \
  'Dir.glob("test/**/*_test.rb").sort.reject { |path| File.read(path).include?("minitest/autorun") }.each { |path| require_relative path }'
```

## 残る制約

- 実ユーザーMP4の手動probeは未指定。全体suiteの既存省略13件は実ファイル3件、隔離binding/MList手動probe10件。
- FFprobeはtype 33のpurlを解釈せず、保存前からSkipping unhandled metadata警告を出す。
  この既存警告を確認し、新しい不正数値index警告がないこととraw完全一致を検証した。
- 安全に拡張できないatom/chunk offset、未対応context、既存fourccとmdtaの混在拒否等の既存制限は維持。
- 通常fourccの既存互換処理は維持する。mdtaのpurlは他のキーと同じ保存処理を使用する。
- 公開は既存v2.3.2.19タグのworkflowでarm64 macOS・Intel macOS・source gemを新規生成する。

判断の理由は[ADR](../ADR/2026-10-14-mdta数値keyとfourcc復元の分離.md)に記録した。
