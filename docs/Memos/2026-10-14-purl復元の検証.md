# purl復元の検証

## 環境と前提

- macOS arm64、Ruby 4.0.7、FFmpeg/FFprobeはPATH上の実行ファイル。
- 作業ツリーの既存拡張bundleを利用。既存参照先の/private/tmpライブラリが削除されていた。
- TagLib v2.3.2（deadc2990767dfbda0701e0ab35fdeea653db08f）を/private/tmp/purl-taglib-sourceへ取得し、
  リポジトリの0001～0004を適用して/private/tmp/purl-taglib-installへ隔離ビルドした。
- DYLD_LIBRARY_PATHでこのnativeライブラリを選択。製品bundleやHomebrew TagLibは変更していない。
- 不足するRuby依存はBUNDLE_PATH=/private/tmp/purl-gemsへインストールした。
- 実ユーザーファイル、MListNew、外部レジストリは変更していない。

## 実装の確認

- 単一mdta・purlなしの復元前拒否、native状態と原本SHAの不変。
- 既存mdta purlのsnapshot復元、raw digestと複数data順の維持。
- 未編集purlのproperty保存時のdata type・raw digest・item位置保持。
- 既存mdirへのpurl復元、再読込値・raw digest・packet hashの一致。
- mdtaのlocale・binary値と通常descriptionを併せた複合復元、繰返し保存、明示的purl削除。
- 複数mdir、handler不一致、不正keys、purl型変更の拒否。
- staging失敗と保存後verify失敗のphase/code/committed、原本SHA不変、一時ファイルのcleanup。
- 複合候補を保留した状態のchapter専用保存拒否。
- FFprobeで新規data index警告なし。既存mdta purlの警告は同じ内容を保持。

FFprobeはログ内のポインタアドレスが実行ごとに変わるため、既存警告の比較時のみ正規化した。
mdta binary type 33はFFprobeの既知のunhandled metadata警告を出すため、そのテストでは
問題となるdata index警告の有無を個別に検証する。

## 結果

| 検証 | 結果 |
| --- | --- |
| purl対象（最終chapterガード追加前） | 15 tests / 139 assertions、失敗0・エラー0 |
| snapshot/property/chapter等の初回対象群 | 108 tests / 1,272 assertions、失敗0・エラー0、omission 1 |
| 全体Test::Unit（最終chapterガード追加前） | 436 tests / 2,948 assertions、失敗0・エラー0、omission 13 |
| 全体Minitest | 12 runs / 24 assertions、失敗0・エラー0、skip 5 |
| 最終chapterガードとverify故障テスト追加後の対象群 | 89 tests / 1,035 assertions、失敗0・エラー0、omission 1 |

全体成功後の変更は、保留snapshotをmetadata_dirty?へ含めるガードと、その故障検証1件。
影響範囲のpurl・chapter・snapshot chapter・atom repair・chapter referencesだけ再検証した。
最終purlテストは16件。全体Test::Unitの13件とMinitestの5件の省略は、実ファイル指定や
別途native probe構築を必要とする既存テスト。

## 実行方法

```sh
BUNDLE_PATH=/private/tmp/purl-gems \
DYLD_LIBRARY_PATH=/private/tmp/purl-taglib-install/lib \
/opt/homebrew/opt/ruby/bin/bundle exec ruby -Itest -e \
'Dir.glob("test/**/*_test.rb").sort.reject { |path| path.match?(/mp4_mdta_(atom_probe|design_contract)_test/) }.each { |path| require_relative path }'
```

全fileの一括requireではautorunが競合してMinitestだけが実行されるため、Test::Unitは上記の除外で実行した。
rake testは起動する子プロセスへDYLD_LIBRARY_PATHが引き継がれず、欠落した旧ライブラリ参照で失敗。
テスト本体は同じRubyから直接requireして実行した。

## 残る制限

単一mdtaへの新規purlは成功扱いにせず、purl_context_creation_unsupportedで復元前に拒否する。
MListNewでpurl省略を削除する場合、この拒否を成果物未確定の失敗として扱う必要がある。
新規context生成、複合contextへのTag/property/chapter直接書込み、実ファイル検証、gem公開は対象外。
