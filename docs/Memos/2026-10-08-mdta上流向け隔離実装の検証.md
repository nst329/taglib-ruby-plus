# mdta上流向け隔離実装の検証

日付: 2026-10-08

## 成果物と適用境界

[提案パッチ](../../patches/taglib/proposals/0001-mp4-mdta-api.patch)にnative実装を保存した。TagLib 2.3.2原始ソースに対する単独パッチであり、既存Ruby向けパッチへ重ねるものではない。本体、上流、インストール済みライブラリには適用していない。隔離コピーでコンパイルした実装と、原始ソースに提案パッチを適用した全8ファイルのbytes一致を確認した。

公開APIはMdtaValue/MdtaItemのPimpl値型、状態判定、キー単位一括置換・削除。従来Ruby版とはnative公開型が異なる。0001単独には既存bindingをそのままリンクしない。後続でadapterとbinding用状態移送パッチ0002を実装し、[Ruby結合検証](2026-10-08-mdtaのRubyBinding結合検証.md)まで完了した。

## 実装した保存契約

- 入力全体を検証し、候補だけを編集してから置換する。空配列・不正キー・長さoverflowを拒否する。
- 通常ItemMapとmdtaの順序付き内部状態を分け、既存indexと未変更raw itemを保持する。
- 編集可能なmdtaはmeta全体を一回で更新する。keys/ilstを旧offsetで個別更新せず、隣接paddingの吸収も行わない。
- tree再接続と変更状態の確定を分離する。Fileのmetadata→Nero→QT保存・再読込照合が全て成功した後に確定する。公開Tag::saveはmetadataの保存・照合で確定する。
- 書込後の失敗・不一致はFileを無効化し、保留中のmetadataとchapter値を保持する。同じFileで再試行せず再openする。
- keys/item/ilst/meta、関連親サイズ、ファイル長、全chunk offsetを事前検証する。chapterの増分は固定box overheadより大きい1MiB＋QT一件あたり512 bytes＋UTF-8 title長×4の保守的上限を使う。境界付近で安全側に拒否する場合がある。
- Unsupportedは部分一覧を公開せず、通常タグだけの保存や後続chapter保存でも迂回しない。

## 検証結果

最終ソースをコンパイルし、19テスト、native 40ケース・369アサーションが成功した。

既存の完全一致・型コピー・複数値・index・新規キー・NUL・空payload・通常タグ・画像・字幕・両chapter・構造拒否の検証に加え、以下を確認した。

| 追加対象 | 結果 |
| --- | --- |
| 後段Nero書込を破棄 | save=false、File無効化、保留metadata/chapter維持、再試行拒否 |
| chapter表現不正の事前拒否 | metadataを含むディスク不変、File維持、入力訂正後に保存成功 |
| 全metadata書込を破棄 | 再読込不一致でsave=false、File無効化、保留値維持 |
| ItemMap直接insert/erase/clear | 保存・再読込で通常タグ変更とmdta維持 |
| Tag::save→File::save | 同じFileで正常保存 |
| 4GiB超の疎な合成MP4 | metadata新規キーと複数値を保存・再読込して完全一致 |
| 上記ファイルへのQT chapter新設 | EOFを32-bit stcoで表せないため書込前に拒否 |
| 原始公開ヘッダーの既存クライアント | 新共有ライブラリで通常保存・再読込・custom read-only IOStream成功 |

原始ヘッダーと提案ヘッダーでビルドした互換クライアントは両方成功し、classサイズはTag=24、File=24、IOStream=16、FileStream=24 bytesで一致（macOS arm64）。これは限定した互換確認であり、全プラットフォームのABI証明ではない。

最終テストログは `/private/tmp/mdta-upstream-implementation-final-test.log`。原本動画を使わず、合成fixtureと各テストのコピーだけで検証した。4GiB超のケースは疎なfree atomを用い、巨大な動画データは作成していない。字幕・音声・動画は安定したtrack IDとpacket hash/時刻で照合する。

## 対応範囲と残る制約

単一の通常32-bit FullBox `moov/udta/meta`、mdta namespaceの有効なkeys/ilstを編集する。同じilstの既知iTunesタグとの混在、繰り返すnumeric親、複数data子、空keys、値なしキーに対応。mdir-onlyは通常APIを維持し、mdta新設は拒否する。

複数meta/udta、別scope、壊れたhandler/keys/index、未知namespace/曖昧なitem、metadata関連のextended-size atom、非FullBox、断片化、STEM編集との併用は初期対象外。必要な長さ/offsetを表せない更新も保存前に拒否する。4GiB超のファイル自体を一律拒否する仕様ではない。

IOStreamのvirtualは追加していない。再読込による検出はflush/close失敗・電源断・全種類のI/O失敗や耐久性を保証しない。native in-place保存の巻き戻しはないため、MListNewの一時コピー→独立照合→置換を維持する。co64自動昇格、全未知atomの位置・順序の網羅、正式な全ABI検証、上流最新版への移植は将来の取り込み時の検討事項。

## 再現手順

Python 3.12以上、git、cmake、C++17コンパイラ、utf8cpp、FFmpeg/FFprobe、fixture生成用Rubyが必要。base-sourceのHEADには原始TagLib 2.3.2を指定する。builderは基準ファイルのSHA-256とパッチ適用可否を検証し、入力ツリーを変更しない。

```sh
python3 test/support/build_mp4_mdta_upstream_probe.py \
  --base-source /private/tmp/taglib-2.3.2 \
  --workdir /private/tmp/mdta-proposal-new
clang++ -std=c++17 -Wall -Wextra \
  -I/private/tmp/mdta-proposal-new/install/include \
  test/mp4_mdta_upstream_probe.cpp \
  -L/private/tmp/mdta-proposal-new/install/lib -ltag \
  -Wl,-rpath,/private/tmp/mdta-proposal-new/install/lib \
  -o /private/tmp/mdta-proposal-new/probe
MDTA_UPSTREAM_PROBE=/private/tmp/mdta-proposal-new/probe \
  python3 test/mp4_mdta_upstream_probe_test.py
```

FFMPEG、FFPROBE、RUBY環境変数で実行ファイルを指定できる。`--prepare-only` は一時コピーへの適用検査までを実行する。native/testの長さ検証関数が同じbytesであることもbuilderで確認する。

互換確認の `test/mp4_mdta_upstream_compat.cpp` は原始公開ヘッダーをincludeし、提案ライブラリへリンクする。今回は原始mp4tag/mp4file/tiostream/tfile/tfilestreamを別の一時includeディレクトリへ取り出し、残りの未変更ヘッダーには隔離installを使用した。原始includeディレクトリを先に指定し、quoted include解決のためinstall/include/taglibも指定する。

## MListNewへの接続

既存Ruby版はtaglib-ruby-plus 2.3.2.7＋対応するローカルTagLibパッチを使い、`replace_mdta_items(key, values)`で復元する。既存set_mdta_itemの契約は変更しない。今回の提案パッチに上流リリース番号は割り当てず、既存gemへの自動適用は行っていない。Ruby adapterは0001＋0002のAPIをextconfで検出し、接続できる。

実装入口と契約は[設計書](../mp4-mdta-upstream-design.md)、判断理由は[ADR](../ADR/2026-10-08-mdta上流向け公開API設計.md)に記録した。
