# mdta一括置換の検証結果

## 環境と前提

macOS arm64、Ruby 4.0.7、TagLib 2.3.2原本にリポジトリの改訂パッチを適用。nativeソース・ビルド・インストール先は `/private/tmp`。FFmpegとFFprobeは `/Users/nasu/Bin`。原本動画は使用せず、合成MP4と既存fixtureの一時コピーを使用した。

## 成功した検証

- Ruby対象: `test/mp4_mdta_replace_test.rb`、8 tests / 135 assertions、失敗・エラーなし。
- 既存mdta API互換性: `test/mp4_mdta_taglib_test.rb`、18 tests / 134 assertions、失敗・エラーなし。
- native直接保存: `test/mp4_mdta_replace_native.cpp`、5値の新規キー作成、3回保存・再読込、完全一致を確認。破棄IOによる保存失敗も確認。
- native既存IO fault probe: `save=0 discarded=7`。
- 構文検査: Ruby API、対象テスト、extconf、APIドキュメント、gemspec。
- 更新パッチのreverse apply check、`git diff --check`。
- gemspecの一覧とGit既存ファイル＋今回の新規ファイルを比較して一致。未コミットの新規ファイルがあるため、Git追跡済みだけを比較するrakeタスクは使用しなかった。

## 全体互換性と既存の失敗

`rake test` ではMinitest側のみが結果に現れたため、Test::Unit群を別プロセスで実行した。

- Minitest群: 12 runs / 54 assertions、失敗・エラー・skipなし。native baselineとIO faultの環境変数を設定して設計契約テストも実行。
- Test::Unit群: 255 tests / 926 assertions、1 failure / 0 errors。
- 唯一の失敗は `test/mp4_items_test.rb:171` の `release borrowed wrappers when the file closes`。追跡数は期待13、実際14。
- 同テスト単独でも28 tests / 101 assertions中の同じ1件が失敗。
- HEADの変更前ラッパーを別ディレクトリでビルドし、変更前nativeパッチも別ビルド・インストールして比較。同じ失敗を再現した。
- Rubyの `lib/taglib/mp4.rb` とversionもHEADへ戻した一時環境で同じ失敗を確認。

この追跡数の失敗は今回のmdta追加以前の実装でも再現する。根本原因の修正は本作業に含めず、回避策やテストの期待値変更も行っていない。全体テスト成功とは報告しない。

## 再現コマンド

TagLibパッチを適用してビルド・インストールし、`TAGLIB_DIR` とmacOSのrpathを指定してMP4 bindingをビルドする。実行時には同じnativeライブラリをロードする。

```sh
DYLD_LIBRARY_PATH=/private/tmp/mdta-install/lib ruby test/mp4_mdta_replace_test.rb
DYLD_LIBRARY_PATH=/private/tmp/mdta-install/lib ruby test/mp4_mdta_taglib_test.rb
DYLD_LIBRARY_PATH=/private/tmp/mdta-install/lib \
  MDTA_BASELINE=/private/tmp/mdta-baseline \
  MDTA_IO_FAULT=/private/tmp/mdta-io-fault \
  SKIP_SWIG=true bundle exec rake test
DYLD_LIBRARY_PATH=/private/tmp/mdta-install/lib bundle exec ruby -Itest -e \
  'Dir["test/**/*_test.rb"].reject { |path| File.read(path).include?("minitest/autorun") }.each { |path| require_relative path }'
```

## 生成ラッパーの制約

SWIG 4.5.1による再生成は、既存の `TagLib::MP4` namespace内での `TagLib::Map` テンプレート宣言で失敗する。既存ラッパーの構造に沿って新APIの変換関数、入口、登録を同期し、C++コンパイルと実行で検証した。`.i` にも対応する定義とnative APIのignoreを追加した。SWIG再生成が成功したとは扱わない。
