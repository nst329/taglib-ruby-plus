# MP4公開APIのI/O性能検証

日付: 2026-10-16
対象: v2.3.2.23（変更前）と本変更。Ruby/native bindingは同じarm64バイナリを使用。
環境: macOS 27.0.1 arm64、Ruby 4.0.7、TagLib 2.3.2。

この記録は前段のI/O改善時点の結果。後続の[header情報・保存snapshotの改善計測](2026-10-16-headerと保存snapshotの再利用検証.md)を併せて参照する。

## 計測方法と制約

入口は `require "taglib_plus"` と `TagLib::Plus::MP4.open` のみ。変更前libを変更開始前に別ディレクトリへ保存し、同じprobeを別プロセスで実行した。

`test/performance/io_meter.c` のdyld interposeでRubyとnativeのread/pread/readv/fread、write/pwrite/writev/fwrite、fcopyfileを計測する。入れ子は重複計上しない。数値はアプリケーションの論理I/O bytesであり、OS cache・stdio buffering・APFS clone等を含む物理ディスク転送量ではない。初期fixtureコピー・require・プロセス起動は計測外。計測器の校正では、1 MiBのRuby read/writeが読取1,048,576・書込1,048,576 bytes、Cのfreadが読取1,048,576 bytesとして観測された。

全体hash回数はSHA256.file呼出しと新しい共有Stream.scanの回数。mdatだけのhashはこの回数に含めず、読取bytesには含める。全媒体コピーはFileUtils.cpとatom計画のwrite_copy、新Streamのdestination付き出力を数える（媒体を含むfixture以上の規模のコピーが対象）。nativeによる候補内の媒体移動はコピー回数に含めず、read/write bytesに含める。

一時領域はwrite/fwrite/fcopyfile/fclose時点の作業ディレクトリのファイル長合計の最大値。原本sourceと公開後のoutputは除く。metadata専用領域も同じTMPDIRへ置く。論理サイズであり、sparseの実割当量ではない。観測点間だけに存在する変化は捉えない。

経過時間は同じ操作をもう一度、カウンタを無効にした別プロセスで実行した値を掲載する。各条件1回であり、cache状態・I/O競合・実行順序による変動を含む。速度倍率を保証せず、I/O bytesと走査回数を受入判断の主指標とする。raw JSONには計測器有効時の時間も残す。

fixtureは既存の12,037 bytesのM4Aと、その末尾へ256 MiBのsparse mdatを追加した268,447,501 bytesのMP4。元の音声・metadata・chunk参照は保持する。大きい追加mdatは未参照の合成payloadであり、大容量の実録画を代表する経過時間ではない。媒体サイズへの比例I/Oの有無を検証する用途で使う。映像・音声・字幕・実chapterの保持は別の受入probeと回帰テストで確認する。

## 操作

| 名前 | 公開操作 |
| --- | --- |
| read | 同じFileでmetadata＋chaptersを2回取得 |
| property | 同じFileでmetadata.propertiesのtitle存在確認を2回 |
| diagnose | metadataとchapter_referencesをそれぞれ2回診断 |
| item | title更新・保存・保存後metadata取得 |
| mdta | locale付きcustom mdta追加・保存・保存後metadata取得 |
| replace | titleだけのsnapshotを完全代入・保存・保存後metadata取得 |
| combined | title＋mdta＋Nero chapterを更新してsave!一回・保存後metadata取得 |
| noop | 無変更の同一path保存 |
| copy | 無変更の別path保存 |

combinedの変更前は既知の制約で拒否されるため、成功した保存との速度比較には使わない。

## 受入結果と残るI/O

- 通常read/property/diagnoseは、256 MiBへ拡大しても約8〜22 KBの読取に留まり、全体hash・全媒体コピーともゼロ。
- 同一pathの無変更保存は読取/書込bytes・hash・コピーが全てゼロ。
- 通常item・mdta・完全置換・metadata＋Nero同時更新は、候補全体コピー一回。metadata生成だけの全媒体コピーはゼロ。全体hash二回は原本コピーと出力の独立読取に共有される。
- 256 MiBでitemの読取は約4.83 GBから537 MB、mdtaは約8.32 GBから537 MBへ減少した。書込はそれぞれ約537 MBから268 MB、約1.88 GBから268 MBへ減少した。
- Nero同時編集も小さい作業領域でatomを生成し、最初のmoov置換に含めた。途中版で観測したnative Nero追記の全媒体移動は最終結果に含まない。
- QuickTime編集は対象外track sampleの原本/出力照合を追加するため、通常metadata保存より読取が多い。nativeのQuickTime writerが候補内で媒体を移動する場合の追加writeも残る。全体コピー回数とwrite bytesを同一視しない。
- statで見えない改変の検出、外部writerとの完全排他は通常モードの保証に含めない。厳密モードと残る競合窓は[設計](../mp4-public-io-design.md)に明記した。

## 再現手順

```sh
clang -dynamiclib -O2 test/performance/io_meter.c -o /private/tmp/plus_io_meter.dylib
# BEFORE_LIB: v2.3.2.23のlib（同じnative bindingを含む）
# large.mp4: 下記の方法等で別途生成する大容量fixture
python3 test/performance/run_plus_mp4_io.py \
  --ruby /opt/homebrew/opt/ruby/bin/ruby \
  --meter /private/tmp/plus_io_meter.dylib \
  --before-lib "$BEFORE_LIB" --after-lib "$PWD/lib" \
  test/data/mp4.m4a /private/tmp/plus-io-large.mp4
```

今回の大容量fixture生成方法（テスト用一時領域だけで実行する）:

```python
import pathlib, struct
with open('/private/tmp/plus-io-large.mp4', 'wb') as output:
    output.write(pathlib.Path('test/data/mp4.m4a').read_bytes())
    output.write(struct.pack('>I4s', 256 * 1024 * 1024 + 8, b'mdat'))
    output.seek(256 * 1024 * 1024 - 1, 1)
    output.write(b'\0')
```

## 回帰検証

- 最終test-unit全体: 515 tests / 3,938 assertions、失敗・エラーなし、13 omissions。
- minitest全体: 12 runs / 24 assertions、失敗・エラーなし、5 skips。
- 公開metadata受入probe: 16 tests / 108 assertions、失敗・エラー・omitなし。
- omit/skipは外部の実ファイル、隔離binding、native design probe用実行ファイル等が未指定の条件による。実ファイルでの追加受入や配布gemの再ビルド・リリースは実施していない。
- 同サイズ変更・mtime復元・path置換・native読取中の変更・公開直前の変更・部分コピー失敗・保存/検証/cleanup失敗・原本維持・Error情報の伝播を確認した。
- 厳密モードはstat観測を固定した内容変更でも拒否する。通常モードと同じ世代検査に加え、所有handleから内容を読むことを確認した。
- metadata完全置換、mdta型/locale/bytes/順序/重複、artwork、purl raw不足と出力locale改変拒否、両chapter形式の同時編集と併存後の再編集を確認した。
- 映像・音声・字幕を含むFFmpeg fixtureにmetadata完全置換とNero/QuickTime同時編集を行い、FFprobeのtrack ID別packet SHAで対象外媒体を独立比較する。chapter追加でstream indexが変わるため、固定indexでは比較しない。
- Ruby構文、Cの警告付きコンパイル、Python構文、gemspec明示一覧、空白検査を実施した。

全体のtest-unit実行は、minitestの自動runnerを分けて行った。

```sh
ruby -Ilib -Itest -e 'Dir.glob("test/**/*_test.rb").sort.reject { |path| File.read(path).include?("minitest/autorun") }.each { |path| require_relative path }' -- \
  --verbose=important-only --no-use-color --progress-style=fault-only --no-show-detail-immediately
ruby -Ilib -Itest -e 'Dir.glob("test/**/*_test.rb").sort.select { |path| File.read(path).include?("minitest/autorun") }.each { |path| require_relative path }'
ruby test/probes/plus_mp4_metadata_contract.rb \
  --verbose=important-only --no-use-color --progress-style=fault-only --no-show-detail-immediately
```

今回のローカル環境ではshoulda-contextを既存の `/private/tmp/taglib-hint-gems` からGEM_PATHへ追加して実行した。新規依存のdownload/installは行っていない。
